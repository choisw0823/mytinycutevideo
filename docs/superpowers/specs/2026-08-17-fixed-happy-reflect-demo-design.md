# Fixed Happy Reflect Demo Design

## Goal

새 발표 슬라이드의 Reflect 메시지와 웹 데모를 일치시킨다. 영상 완성 화면에서 사용자가 Reflect를 실행하면 반려견 `해피`에 관한 고정 Life Insight와 제안을 안정적으로 보여준다.

## User Experience

1. 기존 영상 업로드·생성·저장·재생 흐름을 그대로 완료한다.
2. 완성 영상 아래의 `한 달의 기억 돌아보기` 버튼을 누른다.
3. 같은 화면에서 약 800ms 동안 `기억의 흐름을 살펴보고 있어요...` 로딩 상태를 보여준다.
4. 페이지 이동 없이 고정 Reflect 결과가 나타난다.
5. 완성 영상의 재생, 다운로드, 새 영상 만들기 기능은 계속 사용할 수 있다.

## Fixed Reflect Content

관찰 문구는 다음 문장으로 고정한다.

> 최근 반려견 해피와 함께 하는 시간이 줄었네요

제안 문구는 다음 문장으로 고정한다.

> 해피와 함께 나들이 하는 시간을 가져보면 어떨까요?

결과 화면에는 숫자 기반 `Evidence` 영역과 사진을 표시하지 않는다.

하단에는 다음 세 단계의 의미를 표시한다.

- `Remember`: 과거를 기억한다
- `Reflect`: 지금의 삶을 돌아본다
- `Tomorrow`: 더 나은 선택을 제안한다

## Visual Design

Reflect 결과는 새 슬라이드의 메시지 구조를 웹 카드 크기에 맞춰 재해석한다.

- 전체 너비: `LIFE INSIGHT`, 고정 관찰 문구, 구분선, 고정 제안 문구
- 아래: `Remember → Reflect → Tomorrow` 흐름
- 기존 웹사이트의 크림색 배경, 갈색 강조색, 추억 사진 질감은 유지한다.
- 모바일에서는 문구 카드와 세 단계 흐름을 세로로 배치한다.

## Architecture and Isolation

고정 데모는 `ReflectExperience` 내부의 로컬 상태만 사용한다.

- 버튼 클릭 시 로컬 타이머로 로딩 상태를 보여준다.
- 타이머가 끝나면 고정 결과 상태로 전환한다.
- `/reflect` 네트워크 요청은 보내지 않는다.
- 영상 완료 시 현재 작업을 브라우저 기억 목록에 중복 없이 기록하는 기존 동작은 유지하지만, 고정 결과 문구를 결정하는 데에는 사용하지 않는다.
- 기존 서버 `/reflect` 구현, 브라우저 기억 저장소, 데모 기억 데이터는 삭제하거나 변경하지 않는다.
- 기존 `render_job`, `/jobs`, 작업 폴링, 완료 상태, 결과 재생, 다운로드 로직은 수정하지 않는다.

이 경계로 인해 발표용 Reflect 화면 변경이 현재 영상을 만드는 다른 사용자에게 영향을 주지 않는다.

## Error Handling

Reflect 결과는 고정 문구만 사용하므로 네트워크 실패 상태와 재시도 버튼은 제거한다. 로딩 타이머는 컴포넌트가 사라질 때 정리해 완료 화면을 떠난 뒤 상태가 갱신되지 않게 한다.

## Testing

- 기존 Reflect 브라우저 테스트를 고정 데모 동작에 맞게 수정한다.
- 버튼 클릭 직후 로딩 문구가 표시되는지 확인한다.
- 로딩 뒤 두 고정 문구가 표시되는지 확인한다.
- `Evidence`가 표시되지 않는지 확인한다.
- `Remember`, `Reflect`, `Tomorrow` 세 단계가 표시되는지 확인한다.
- Reflect 실행 중 `/reflect` 네트워크 요청이 발생하지 않는지 확인한다.
- 결과가 나타난 뒤에도 완성 영상이 DOM에 남고 URL이 `/create`인지 확인한다.
- 기존 전체 Playwright 테스트, Python 테스트, 린트, 프로덕션 빌드를 다시 실행한다.

## Non-Goals

- 업로드 영상이나 프롬프트에서 반려견 이름을 추출하지 않는다.
- 실제 기억의 횟수나 시간을 계산하지 않는다.
- Reflect 결과를 사용자마다 바꾸지 않는다.
- 기존 서버 Reflect API를 제거하거나 다시 설계하지 않는다.
- 서버나 프런트엔드를 자동 배포하지 않는다.
