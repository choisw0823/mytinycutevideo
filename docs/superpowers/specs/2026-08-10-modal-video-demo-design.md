# My Tiny Cute Video — Modal 데모 설계

## 목표

기존 이미지 무드보드 앱을 로그인 없는 자동 브이로그 생성 데모로 전환한다. 웹사이트는 Lovable에서 배포하고, 영상 업로드 이후의 분석·편집·렌더링은 Modal에서 기존 `G-SULEE/webapp/pipeline.py`를 실행해 처리한다.

발표용 단일 사용자 데모가 목표다. 사용자 계정, 장기 파일 보관, 협업, 결제, 작업 이력은 범위에서 제외한다.

## 사용자 흐름

1. 사용자가 메인 화면에서 `시작하기`를 누른다.
2. 생성 화면에서 ZIP 파일 하나 또는 영상 파일 여러 개를 선택한다.
3. 원하는 편집 방향을 한국어 프롬프트로 입력한다.
4. `영상 만들기`를 누르면 파일을 Modal에 업로드한다.
5. 업로드 후 Modal 비동기 작업이 시작된다.
6. 프런트엔드는 1초 간격으로 작업 상태를 조회한다.
7. 현재 단계, 진행률, 캡션 썸네일을 화면에 순차적으로 표시한다.
8. 완료되면 결과 MP4를 재생하고 다운로드할 수 있다.
9. 사용자는 `새 영상 만들기`로 초기 상태로 돌아갈 수 있다.

## 시각 방향: 흩어진 기억 조각

전체 경험은 `파일을 처리하는 도구`보다 `흩어진 순간을 하나의 기억으로 엮는 공간`처럼 보이게 한다.

- 따뜻한 아이보리 배경, 빛바랜 사진 톤, 짙은 잉크색 텍스트를 기본으로 한다.
- 사진은 폴라로이드나 인화 사진처럼 약간씩 회전하고 겹쳐 배치한다.
- 작은 날짜, 장소, 짧은 손글씨풍 메모를 보조 요소로 사용하되 실제 사용자 정보처럼 보이는 가짜 사실은 넣지 않는다.
- 종이 질감, 약한 필름 그레인, 부드러운 그림자를 절제해서 사용한다.
- 사진은 천천히 떠 있거나 포인터에 미세하게 반응하지만, 멀미를 유발하는 큰 이동과 자동 반복 애니메이션은 피한다.
- 핵심 입력과 진행 상태는 항상 중앙의 깨끗하고 읽기 쉬운 영역에 유지한다.
- `prefers-reduced-motion` 환경에서는 장식 움직임을 끈다.

## 화면 구조

### 메인 `/`

- 기존 Konva 편집 캔버스는 제거한다.
- 기존 랜딩 이미지는 화면 가장자리의 비대칭 사진 콜라주로 재사용한다.
- 사진마다 작은 회전, 서로 다른 크기, 일부 겹침을 적용해 테이블 위에 추억 사진을 흩뿌린 느낌을 만든다.
- `My Tiny Cute Video` 브랜드, `흩어진 순간을 한 편의 기억으로`라는 메시지, `시작하기` 버튼을 중앙에 배치한다.
- 중앙 콘텐츠 주변은 여백을 확보해 사진이 제목과 버튼을 가리지 않게 한다.
- 로그인, 회원가입, 대시보드 진입 요소를 제거한다.
- `시작하기`는 `/create`로 이동한다.

### 생성 `/create`

하나의 페이지가 작업 상태에 따라 네 화면으로 전환된다.

#### 입력

- 가장자리에는 랜딩과 동일한 사진 콜라주 문법을 유지하되 채도와 대비를 낮춰 입력을 방해하지 않게 한다.
- 드래그 앤 드롭 파일 영역
- ZIP 한 개 또는 지원 영상 여러 개 선택
- 선택 파일명, 개수, 전체 용량 표시
- 편집 프롬프트 입력란
- `영상 만들기` 버튼
- 파일을 선택하면 영상에서 가져온 첫 프레임 썸네일을 작은 인화 사진처럼 파일 영역 주변에 추가한다.

#### 업로드

- 업로드 진행률과 전송 용량 표시
- 중복 제출 방지
- 업로드 실패 시 재시도 제공

#### 처리

- 중앙에는 필름 릴을 연상시키는 절제된 애니메이션 로더를 사용한다.
- 현재 단계와 세부 메시지
- 전체 단계 목록과 완료 체크
- 캡션 단계에서 썸네일을 작은 인화 사진처럼 순차적으로 펼친다.
- 새로 분석된 장면은 콜라주에 추가되고, 해당 사진 아래에 화면 설명이나 감지 대사를 짧은 메모처럼 표시한다.
- 진행이 계속되면 흩어진 사진들이 아래쪽의 시간 순서 리본으로 천천히 정돈되어 `기억이 한 편의 이야기로 묶이는` 변화를 보여준다.
- 다음 단계를 표시한다.
  - 압축 해제
  - 영상 정규화
  - 장면 분할
  - 캡션 및 대사 분석
  - 에피소드 구성
  - 클립 조립
  - 최종 렌더링

#### 완료

- 정돈된 사진 리본이 결과 영상 프레임을 둘러싸도록 하여 처리 화면의 시각적 흐름을 이어간다.
- 결과 MP4 플레이어
- 길이와 파일 크기
- `MP4 다운로드`
- `새 영상 만들기`

오류가 발생하면 실패 단계, 이해 가능한 오류 메시지, 다시 시도 버튼을 표시한다.

## 시스템 구조

### Lovable 웹 앱

- 현재 TanStack Start와 Tailwind 기반을 유지한다.
- Lovable가 프런트엔드와 얇은 서버 경계를 배포한다.
- Modal API URL은 환경 변수로 관리한다.
- 대용량 파일은 Lovable 서버를 경유하지 않고 브라우저에서 Modal 업로드 API로 직접 전송한다.
- 작업 생성 후 받은 `job_id`로 상태를 폴링한다.

### Modal API

Modal은 다음 HTTP API를 제공한다.

- `POST /jobs`
  - ZIP 또는 여러 영상과 프롬프트를 받는다.
  - 입력 검증 후 작업 디렉터리에 저장한다.
  - 여러 영상은 기존 파이프라인 입력 형식에 맞게 ZIP으로 묶는다.
  - 비동기 렌더 함수를 시작하고 `job_id`를 반환한다.
- `GET /jobs/{job_id}`
  - 누적 이벤트, 다음 이벤트 인덱스, 완료 여부, 오류 여부를 반환한다.
- `GET /jobs/{job_id}/files/{path}`
  - 작업 중 생성된 썸네일을 제공한다.
- `GET /jobs/{job_id}/result`
  - 완료된 MP4를 스트리밍한다.

발표 중 브라우저 업로드를 허용하도록 Lovable 배포 도메인과 로컬 개발 주소만 CORS 허용 목록에 넣는다.

### Modal 작업 실행

- `G-SULEE/webapp/pipeline.py`를 Modal 배포 코드와 함께 패키징한다.
- Modal 이미지에 Python, FFmpeg, OpenAI SDK, PyTorch, SoundFile 등 실행 의존성을 설치한다.
- `OPENAI_API_KEY`는 Modal Secret에서 읽는다.
- BGM과 폰트는 이미지 또는 Modal Volume에 포함한다.
- 입력, 중간 산출물, 결과 MP4는 작업별 디렉터리에 저장한다.
- 기존 `emit(event)` 콜백을 작업 상태 저장소에 연결한다.
- 동시 렌더 작업은 1개로 제한한다.
- 작업 제한시간은 영상 렌더링을 고려해 1시간으로 설정한다.

## 상태 모델

작업 상태는 다음 필드를 가진다.

```json
{
  "job_id": "abc123",
  "state": "queued | uploading | running | completed | failed",
  "stage": "caption",
  "events": [],
  "done": false,
  "error": null,
  "result": null
}
```

Modal Dict는 작업 상태와 진행 이벤트를 저장한다. Modal Volume은 입력과 산출물을 저장한다. 상태와 파일은 데모용 임시 데이터이며 장기 보존을 보장하지 않는다.

프런트엔드는 `since` 인덱스를 사용해 새 이벤트만 요청하고, 완료 또는 실패 상태가 되면 폴링을 중지한다.

## 입력 제한과 안전장치

- 허용 입력: `.zip`, `.mp4`, `.mov`, `.m4v`, `.avi`, `.mkv`
- ZIP 내부에서는 동일한 영상 확장자만 처리한다.
- 최대 파일 수와 전체 업로드 용량을 프런트엔드와 Modal 양쪽에서 검증한다.
- ZIP 경로 순회 공격을 차단하도록 안전하게 압축을 해제한다.
- 파일명은 서버에서 생성한 작업 경로 아래 안전한 이름으로 정규화한다.
- 렌더 버튼을 한 번 누르면 업로드 또는 작업 생성이 끝날 때까지 비활성화한다.
- Modal 컨테이너 동시 실행 수를 1개로 제한한다.
- 실패한 작업은 원인 메시지를 남기고 결과 다운로드를 제공하지 않는다.
- 발표가 끝나면 Modal 앱을 중지하거나 엔드포인트를 제거한다.

## 인증과 비용 관리

사용자 로그인과 회원가입은 구현하지 않는다. 발표 시점에만 Lovable URL을 공유한다.

Modal 사용을 위해 프로젝트 소유자는 다음을 준비한다.

1. Modal Starter 계정 생성
2. 로컬에서 Modal CLI 인증
3. Modal Secret에 `OPENAI_API_KEY` 등록
4. Modal 앱 배포
5. 배포된 API URL을 Lovable 환경 변수에 등록

공개 URL 오용 위험은 다음으로 낮춘다.

- 발표 시간 외 Modal 앱 중지
- 동시 컨테이너 1개
- 파일 수·용량 제한
- 허용 Origin 제한
- Modal 예산 알림 설정

Origin 제한은 브라우저의 정상 요청을 제한하는 장치이며 완전한 인증 수단은 아니다. 발표 이후 엔드포인트를 중지하는 것을 최종 보호 수단으로 삼는다.

## 기존 코드 변경 범위

### 제거

- 로그인 및 회원가입 라우트
- 인증 라우트 가드와 루트 인증 초기화
- Supabase 및 Lovable Auth 의존 흐름
- 대시보드 및 이미지 무드보드 진입 흐름
- 랜딩 Konva 캔버스

### 재사용

- TanStack Start 라우팅과 Cloudflare/Lovable 빌드 구성
- Tailwind 디자인 토큰
- Button, Card, Progress, Alert, Textarea 등 UI 컴포넌트
- Sonner 알림
- `G-SULEE/webapp/pipeline.py` 영상 처리 로직

### 추가

- `/create` 라우트
- 업로드·진행·결과 React 컴포넌트
- Modal API 클라이언트와 타입
- Modal 배포 앱, 작업 상태 저장, 파일 API
- 입력 검증과 오류 매핑

기존 무드보드 소스는 새 데모에서 참조되지 않도록 제거하되, 자동 생성되는 라우트 트리는 빌드 과정으로 갱신한다.

## 오류 처리

- 네트워크 오류: 업로드 재시도 안내
- 잘못된 파일: 업로드 전에 즉시 안내
- Modal 작업 대기: 대기 상태와 순번 대신 `작업 준비 중` 표시
- 파이프라인 오류: 마지막 성공 단계와 서버 메시지 표시
- 상태 조회 실패: 제한 횟수만큼 자동 재시도 후 수동 재시도 제공
- 결과 다운로드 실패: 렌더를 다시 실행하지 않고 다운로드만 재시도
- 페이지 새로고침: 로컬 저장소의 마지막 `job_id`가 유효하면 상태 복원

## 테스트와 검증

### 프런트엔드

- ZIP과 복수 영상 선택 검증
- 프롬프트 필수 입력 검증
- 입력 → 업로드 → 처리 → 완료 상태 전환
- 업로드와 작업 실패 화면
- 새로고침 후 작업 복원
- 모바일 레이아웃에서 파일 목록과 진행 상태 가독성

### Modal

- 지원 파일 업로드와 ZIP 생성
- 잘못된 확장자와 손상 ZIP 거부
- 비동기 작업 ID와 상태 조회
- 파이프라인 이벤트 누적 및 증분 조회
- 성공 결과 스트리밍
- 실패 상태와 오류 메시지
- 동시 실행 제한

### 통합 확인

- 작은 H.264 MP4 2~3개로 전체 흐름 실행
- Lovable 배포 도메인의 CORS 확인
- 진행 단계가 실제 파이프라인 이벤트와 일치하는지 확인
- 생성 MP4 재생과 다운로드 확인
- `npm run lint`, `npm run build`, Playwright 핵심 흐름 검사

## 완료 기준

- 로그인 없이 메인에서 생성 화면으로 진입한다.
- ZIP 또는 여러 영상과 프롬프트를 제출할 수 있다.
- 기존 G-SULEE 파이프라인이 Modal에서 비동기로 실행된다.
- 사용자는 현재 처리 단계와 진행 상황을 확인할 수 있다.
- 성공 시 브라우저에서 결과 MP4를 재생하고 다운로드할 수 있다.
